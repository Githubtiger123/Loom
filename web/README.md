# Loom 前端

全新前端基础工程，使用 React 19、TypeScript 严格模式、Vite、React Router、TanStack Query、React Hook Form 和 Zod。页面以中文为主，使用真实后端接口，不提供模拟业务数据。

## Atomus 接入

使用 [Atomus 官方设计系统](https://docs.atomus.io/)，组件与语义样式已放入 `vendor/atomus/`。官网称 Atomus 4.0，本次选定提交的 React 源码包版本为 **4.1.0**；提交、许可证和更新约定见 [来源记录](vendor/atomus/UPSTREAM.md)。

`@atomus` 直接指向官方 React 源码，主入口加载官方 token 和组件 CSS，无需先单独构建组件包。保留 MIT LICENSE 与 NOTICE；没有购买或下载 Figma 商业模板。字体和图标随本地依赖提供，无需运行时加载外部 CDN。

## 环境准备

Node.js 要求 **22.12 或更高版本**，使用 npm 和已提交的 `package-lock.json`。本次已经安装依赖并生成锁文件，安装使用 `--ignore-scripts`，未执行任何生命周期构建脚本。

在新环境恢复依赖时，在本目录执行：

```powershell
npm ci --ignore-scripts
Copy-Item .env.example .env.local
```

配置项：

| 配置                            | 说明                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------- |
| `LOOM_API_PROXY_TARGET`         | 开发服务器转发 `/api` 的后端地址，例如 `http://127.0.0.1:8080`；仅供本地 Vite 配置读取 |
| `VITE_AUTH_MODE=local`          | 本地账号密码认证；后端必须相应启用本地认证                                             |
| `VITE_AUTH_MODE=trusted-header` | 显式使用现有可信身份代理；前端不构造身份头、不负责统一登录                             |
| `VITE_NOTEBOOK_ORIGIN`          | Notebook 的独立 HTTPS 来源，与后端 `auth.notebook_origin` 完全一致，不带路径或尾斜杠   |

`VITE_*` 会进入浏览器代码，禁止放密钥、JWT 或数据库凭据。`.env.local` 不纳入版本管理。

后续经用户允许运行时，开发入口为 `npm run dev`，构建命令为 `npm run build`。本次没有执行这些命令，也没有执行测试、类型检查或 lint。安装成功仅表示依赖准备完成，不代表集成已经验证。

## 认证与部署接线

所有请求走当前来源下的 `/api/v1`，接口封装在 `src/lib/api.ts`。Access JWT 只保存在内存中；刷新依靠服务端设置的 HttpOnly Cookie，浏览器刷新页面时恢复会话。多个并发的 401 共用刷新请求，写操作不会自动重试；认证刷新后仅重放一次原请求，并沿用原 Idempotency-Key。退出登录和修改密码后清理查询缓存，会话变更后拒绝旧请求结果。

登录返回地址由认证策略统一校验，不自动返回 `/login` 或 `/password`（包含旧历史状态、尾斜杠及查询参数的形式）；来自 `/account/password` 的重新登录回到个人中心。改密成功后清空输入与会话，仅由页面守卫跳转登录；新登录仍以服务端 passwordChangeRequired 决定是否强制改密，false 时回业务页面或工作空间首页。主动改密统一进入个人中心，旧 `/password` 地址在非强制改密时转向个人中心的改密页。

本地密码认证要求 **HTTPS**，后端 `auth.public_origin` 必须和浏览器来源（协议、主机、端口）完全一致。后端会校验 Origin，并设置 Secure Cookie，不能用普通 HTTP 页面完成该登录流程。不要为了调试关闭这些校验。

开发服务器默认监听 `127.0.0.1:5173`；需要在它前面放可信证书的 HTTPS 反向代理，例如浏览器访问 `https://loom.localhost`，后端 `auth.public_origin` 同样配置为 `https://loom.localhost`。代理保留浏览器 Host、Origin，Vite 再把 `/api` 转发给 `LOOM_API_PROXY_TARGET`。如果选用其他开发主机名，需要显式加入 Vite `server.allowedHosts`，不能设置为允许任意主机。认证后端和可信身份代理的初始化步骤见 [后端认证说明](../platform/docs/authentication.md)。

生产环境需要同源提供静态文件和 `/api`：业务 API 转发到 Loom 后端，页面路由使用 SPA history fallback 回退到 `index.html`，不要把 `/api` 错误也回退为 HTML。外部身份模式必须经过可信认证代理，不能在浏览器伪造用户头。

前端不会用 `/me.permissions` 的全局权限推导组内权限。新增 `GET /groups/{gid}/me/permissions` 返回当前用户的空间权限快照，导航与 Notebook 按钮使用它控制入口，Notebook 再结合当前负责人判断对象归属。查询失败时隐藏写操作；读取和写入仍由后端最终授权。所有组内查询键包含 groupId，切换空间会卸载旧页面。后续各模块继续接入这一公共能力，不在浏览器按角色名称猜测授权。

## 本次完成的页面与接口

| 页面           | 当前能力                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| 登录与会话     | 密码登录、刷新恢复、退出、首次登录强制改密、认证失败展示                                                          |
| 个人中心       | 查看个人资料、修改本地密码、设备会话管理、退出全部设备，与业务页面共用账号入口                                    |
| 平台管理       | 用户分页/详情、本地或外部身份登记、启用/禁用、密码设置、全局角色分配、自定义角色及权限点、审计分页                |
| 设备会话       | 我的有效会话、撤销单设备、退出全部设备、管理员查看和撤销目标本地用户会话                                          |
| 空间选择与布局 | 获取真实空间列表、分页、导航、浅色/深色主题、响应式布局                                                           |
| 空间管理       | 创建空间、名称/描述局部编辑、状态观测、停用恢复、非空删除保护与操作进度                                           |
| 成员与授权     | 查看成员、多角色/有效期、添加已有用户、角色替换、移除、负责人交接、授权/撤权落实列表及分页                        |
| 资源配额       | 真实集群快照、请求/实际额度、已分配/业务预留/剩余预算、平台级配额调整与原因记录                                   |
| Notebook       | 搜索/范围/状态/类型筛选、创建、编辑、打开、启停删除、分区详情、事件、诊断、有界日志、资源用量、操作进度与失败重试 |
| Pipeline       | 定义列表、详情、创建定义、读取版本列表                                                                            |
| 模型管理       | 模型列表、详情、登记模型、读取版本列表                                                                            |
| KServe         | 服务列表、详情、状态、同步时间与服务地址文本展示                                                                  |

Notebook 镜像读取后端镜像目录，提交 imageId 及对应 serverType；创建页面可设置 GPU 和空闲停止策略，默认 0 GPU、不自动停止、新建工作目录，也可分页选择属于自己的空闲独占目录并固定其 revision 复用。后端目前没有可信 kernel 活动源，配置空闲策略不代表自动回收已经可用，诊断会明确说明。删除固定 `deleteWorkspace: false`，保留目录；启停删除携带当前 revision。HTTP 202 仅表示受理，操作单与资源状态分别查询，列表每 5 秒刷新。Pipeline、模型版本目前最多展示前 200 条，并在界面说明此限制。

Notebook 打开已接 `access` 与 `notebook-session`：先重新检查对象访问状态，再校验受信域名和 Notebook 路径，本地认证模式在该域名设置 HttpOnly Cookie，最后打开环境。JWT 不进入 URL、localStorage 或任意远程主机；预留窗口被阻止时提示用户允许弹窗，建立会话超时或失败则关闭预留窗口。生产建议使用同站不同子域的 HTTPS 主机，第三方 Cookie 被浏览器禁用时跨站方案可能受限。Notebook Cookie 不延长 Access 有效期，已打开环境的自动续期暂未实现，过期后需回到平台重新打开。

空间创建入口在空间列表；组内新增“成员与授权”“资源配额”“空间设置”。创建自动授予当前用户业务负责人，底层 Profile owner 继续使用平台配置的管理身份。添加成员按已有用户 ID 授权，不创建账号或发送邀请，不要求普通空间负责人获得全站用户目录权限。角色有效期使用本地时间输入、UTC 提交。负责人交接默认保留自己的负责人角色；交接、自降权或移除自己后回空间列表查看操作结果。

空间元数据编辑只提交变化字段并携带旧名称/描述；成员替换和移除携带有效绑定的 ID + version 快照，后端在事务锁内比较，冲突返回 409 且前端保留草稿。成员移除复用角色替换接口提交空 roles，以同时应用并发保护和原有撤权/资源策略。配额更新使用固定空间 revision，只有全局 `group.quota.update` 可调整，空间负责人不自动拥有。以上兼容扩展无需改表，见 [空间管理接口约定](../platform/docs/group-management.md)。

成员与集群授权分别每 5 秒读取，授权面板仅在可见时挂载；配额每 15 秒读取可信集群快照，失败时不展示陈旧成功数据或假零值。空间状态每 5 秒、空间列表每 10 秒更新，后台网络失败不主动清空编辑草稿。普通空间负责人目前只能查看授权失败及操作单，失败任务的管理重试仍由具备后端要求权限的管理员处理，界面不放宽这一限制。

首页、空间业务、平台管理和个人中心共用右上角账号入口：个人中心、主题切换、退出登录，以及按 `user.read`、`user.manage`、`role.manage`、`audit.read` 显示的平台管理。不把空间 Owner 当成平台管理员，也不推断 user.manage 包含 user.read。本地用户登记后单独设置初始密码；外部身份登记不创建身份提供方账号，未核验时保持待开通。密码重置成功后目标旧会话失效并强制改密，不将密码放进 mutation variables、查询缓存或幂等指纹。

个人中心 `/account` 使用独立左侧导航，集中个人资料、`/account/password` 修改密码和原地址 `/account/sessions` 设备会话。资料复用 `/me`，只读展示真实用户 ID、账号、展示名、邮箱、身份来源、状态和创建时间；没有新增个人资料编辑接口。首次登录强制改密仍走独立 `/password` 页面，两处复用同一密码表单，密码不进入 mutation variables。退出登录经后端确认后清理会话与缓存，失败保留明确提示；外部统一认证模式不调用本地改密或退出接口，退出按钮禁用，提示通过组织认证入口管理，避免宣称已退出外部身份源。

全局角色绑定完整替换并携带旧绑定 ID/version；角色定义遵循后端 PUT 整体替换契约，并用 expectedVersion 保护固定编辑基线。内置角色只读，自定义角色可编辑/停用，角色权限按模块分组且显式选择。用户状态变更携带 expectedAuthorizationVersion；409 不自动覆盖或丢弃草稿。新增的三个只读接口和兼容字段见 [平台管理契约](../platform/docs/platform-administration.md)，无需改表。

会话面板只展示同认证域内的有效 family 编号与建立/刷新/过期时间，不展示 Token、摘要或没有采集的 IP/设备名。管理员只能在 user.manage 下查看和撤销目标本地用户会话。外部 SSO 模式不调用本地会话 API。用户与审计筛选目前仅覆盖已加载分页，不是全库搜索；审计按 ID 正序读取，查看关联操作单仍重新授权。

新增组内“工作目录”入口：分页台账、详情、容量/可信已用量、数据保留状态、当前及历史实例引用、关联已停止实例、安全解除关联、独立交接数据负责人和显式删除。目录列表每 10 秒读取，筛选仅覆盖已加载页。无可信文件系统指标时显示“暂无可信指标”，不以 PVC 容量冒充实际已用量；不提供文件浏览、任意 PVC 导入、扩容或快照备份。

Notebook 详情可进入实例负责人交接，已登记关联目录通过只读 workspaceId 跳转目录页，目标接口仍重新授权。实例交接携带 ownerRevision，不交接文件；目录交接携带目录 revision，要求关联实例先停止并转给同一人，或者先解除引用。表单均明确目标用户 ID、原因和名称确认，成功后返回列表查看操作结果，不保留旧对象权限下的详情。删除目录要求无任何历史引用、完整 PVC 名称确认、原因及显式解除已有保留保护；没有强制删除开关。接口约定见 [生命周期与目录接口](../platform/docs/lifecycle-api.md)。本次仅扩展 Notebook 只读返回字段，无新表或迁移。

尚未实现 Notebook 环境变量/标签编辑、Pipeline 版本导入/编辑/运行/DAG、模型版本和产物写入、KServe 创建/部署，以及统一任务运维台与全库用户/审计搜索。Notebook 日志遵循现有后端的快照接口，不支持 follow；本轮没有新增 Notebook 在线终端或虚构后端不存在的终端 API。

本阶段工程规范、模块拆分及后续顺序见 [前端工程规范与实施进度](docs/engineering.md)。

平台管理与空间业务共用左右布局：左侧按权限展示模块，右侧提供统一顶栏与内容区。Notebook 创建在列表上打开大号弹窗，内部滚动、底部操作固定，关闭或返回时对未提交内容就地确认；原有创建地址仍可直接访问，编辑与交接继续使用独立页面。布局调整不改变后端接口或集群校验，本轮未运行项目、测试、类型检查或编译。

## 目录与开发规范

工作空间的页面地址统一使用 `/workspaces/:groupId`，例如 `/workspaces/1`、`/workspaces/1/notebooks`、`/workspaces/1/pipelines`；创建空间为 `/workspaces/new`。旧 `/g/:groupId/...` 和 `/spaces/new` 仅保留兼容重定向，保留子路径、查询参数、锚点和操作导航状态。前端页面命名不改变后端 `/groups` API、数据库 ID 或 Notebook 自身 `/notebook/...` 访问地址。路由参数内部保留 groupId，避免与目录资产的 workspaceId 混淆。

```text
src/app/                 路由、会话守卫、应用布局
src/components/          业务通用反馈与异步操作弹窗
src/features/auth/       登录与改密
src/features/account/    个人资料、个人中心布局及账号安全入口
src/features/admin/      全局用户、角色绑定、权限定义与审计
src/features/security/   我的/受管用户设备会话与撤销确认
src/features/workspaces/ 空间选择
src/features/groups/     空间生命周期、成员角色、授权落实与配额
src/features/notebooks/  开发环境页面、接口、校验、状态规则与职责组件
src/features/storage/    Notebook 目录资产、引用管理与安全数据处置
src/features/ownership/  实例与目录复用的显式交接表单和输入契约
src/features/resources/  Pipeline、模型、推理的基础页面
src/lib/                 API、会话、查询客户端与类型
src/styles/              使用 Atomus 语义变量的业务样式
vendor/atomus/           固定提交的官方组件与样式
```

组件优先使用官方 Atomus API，业务适配放到 `src/`，不直接改 vendor；不散落 fetch、远程地址、颜色值或认证逻辑。保留加载、空列表、403、请求失败四种状态。代码约定见 [AGENTS.md](AGENTS.md)。ESLint 与 Prettier 配置已提供，按当前用户要求未运行 lint、测试、类型检查、编译或项目。
