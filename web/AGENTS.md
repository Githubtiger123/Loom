# Loom 前端约定

- 不新增测试，不运行测试、类型检查、编译或开发服务器，除非用户明确改变约束。
- React + TypeScript 严格模式；路由集中 src/app/router.tsx，业务按 features 组织。
- 优先使用 @atomus 官方组件；不得猜测组件 props。vendor/atomus 保留上游源码和许可证，业务适配写在 src/components。
- 颜色、间距、字体和圆角使用 Atomus 语义变量；不在业务 CSS 写散落的颜色值或覆盖上游 token。
- API 统一经过 src/lib/api.ts；禁止在组件内拼接任意远程地址、持久化 JWT 或读取 Refresh Cookie。
- 组内查询键必须包含 groupId；组切换卸载旧页面，写操作不自动重试，Idempotency-Key 每次用户意图生成一次。
- 加载、空数据、无权限、网络失败必须区分，不使用模拟成功数据或以 HTTP 202 代表工作负载就绪。
- 不根据 /me 的全局权限推导组内权限；后端仍是最终授权方。
- 第三方下载和依赖安装允许用于环境准备，安装必须 --ignore-scripts，不执行生命周期构建脚本。
- 新业务模块按 api.ts（接口与查询键）、types.ts（契约）、form-schema.ts（表单校验）、policy.ts（前端状态规则）、页面与 components/ 分层。页面负责协调，不堆砌表格、确认弹窗、日志及表单细节；模块内组件不随意提升到全局公共目录。
- 抽取组件以独立职责、独立交互和真实复用为依据，不按机械行数拆分，也不建立包揽全部业务的通用 CRUD 组件。
- 长表单使用独立页面，共用字段块；基于固定 revision 编辑，仅提交改动字段。409 不强制覆盖或清空输入，成功前不展示资源已就绪。
- 写请求遇到不确定失败，未改变的同一意图复用幂等键；不得因点击重试生成重复任务。离开提交中的页面后，返回结果不应强制把用户导航回来。
- 日志、事件等含用户内容的查询仅在可见面板加载，查询键包含空间、实例及修订/负责人版本；撤权、失败或身份变化时不继续展示陈旧内容。
- 组内有效权限使用 /groups/{gid}/me/permissions 获取，结合对象归属控制入口；权限快照只影响交互，后端仍逐请求授权。
