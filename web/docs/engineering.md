# 前端工程规范与实施进度

## 交付边界

界面需要能解释真实业务过程：谁有权操作、请求是否受理、后台是否执行完成、集群是否就绪。演示只使用后端真实返回的数据，不伪造成功状态、运行记录、使用率或模型产物。当前仅完成源码实现和文档核对，按用户要求未测试、未类型检查、未编译、未启动，不能据此认定真实集成已经通过。

## 分层与组件拆分

Notebook 作为新模块实现的参考：

| 层             | 当前文件                            | 职责                                                                          |
| -------------- | ----------------------------------- | ----------------------------------------------------------------------------- |
| 通用请求       | `src/lib/api.ts`                    | 同源请求、错误信封、内存 Access、单飞刷新、会话隔离、受信 Notebook 会话初始化 |
| 业务数据访问   | `features/notebooks/api.ts`         | 业务路径、入参、返回类型、查询键、写操作                                      |
| 业务契约       | `features/notebooks/types.ts`       | 跟随后端 DTO，区分详情、日志、诊断、用量                                      |
| 表单校验       | `features/notebooks/form-schema.ts` | 必填、名称、字符长度和枚举，不代替后端数量/配额校验                           |
| 状态规则       | `features/notebooks/policy.ts`      | 归属判断、繁忙状态、是否允许编辑运行配置                                      |
| 访问地址校验   | `features/notebooks/access.ts`      | 明确受信来源与 Notebook 路径，拒绝任意地址跳转                                |
| 页面           | 列表、创建、编辑、详情              | 协调路由、查询、面板和用户意图，不承担所有呈现细节                            |
| 模块组件       | `features/notebooks/components/`    | 表格、筛选栏、共享表单字段、操作确认、打开按钮、各详情面板                    |
| 跨模块公共组件 | `src/components/`                   | 错误/空状态、异步操作、文本域、未保存修改提醒                                 |

组件按照独立职责、独立状态、真实复用拆分，而不是按固定行数拆碎。只在 Notebook 内使用的组件保留在模块内部；不要预先抽象一个覆盖 Pipeline、Notebook、模型、推理服务生命周期的万能 CRUD。原有其他模块的基础页仍待各自业务阶段细化。

Atomus 基础组件优先使用真实 props 与 slot；没有 React 导出的 Textarea 使用可访问原生字段和语义变量组合，不猜测组件名、不修改 vendor。业务表单使用独立页面，短确认使用 Modal，不叠加弹窗。

## Notebook 操作约定

- 创建：受管镜像选择自动携带 serverType；支持名称、展示名、描述、CPU、内存、GPU、空闲策略、新建目录容量或按固定目录 revision 复用本人的空闲独占目录。
- 编辑：固定读取时的 revision；只提交 dirty 字段，保留未编辑的环境变量、标签；CPU/内存/GPU 仅在停止已落实且修订一致时开放。资源更新后不自动启动。
- 启停删除：独立确认，提示影响，携带 revision；固定保留工作目录，不提供容易误删数据的附带目录删除开关。
- 幂等：同一个表单或确认弹窗里，未变化的请求体在不确定失败后使用同一 Idempotency-Key；不自动重试写操作。成功后的新意图使用新键。
- 冲突：409 后保留输入，不自动拉取新 revision 强制提交；返回详情确认新状态后重新编辑。403 明确显示权限不足。
- 离开：未提交表单在站内导航和浏览器关闭时提醒；已提交请求离开后可能继续处理，异步返回不将用户强行导航回原模块。
- 状态：202 只表示受理。列表/详情每 5 秒读取；操作单每 2 秒读取到终态；失败操作通过 Notebook 专用 retry 接口重新授权后申请重试。
- 展示：期望/观测状态、期望/已落实修订、最近同步时间分开展示；不把数据库 status 单独作为打开环境的依据。

## 权限与访问

`GET /api/v1/groups/{gid}/me/permissions` 只返回当前调用者的空间权限：`userId`、`groupId`、`permissions`、`evaluatedAt`。后端复用既有有效绑定、用户状态、角色启用、有效期与 scope 条件，以 GORM 一次查询聚合普通成员权限；有效平台管理员返回已定义的空间权限。

这是 UI 提示快照，不是签发给浏览器的授权凭证。对象负责人、空间状态、原生访问落实、revision、集群身份仍由每个业务接口重新判断。前端每 30 秒更新权限，失败时隐藏写入口，不从全局 `/me.permissions` 推断空间权限。导航和 Notebook 入口已使用该能力，其他模块的细粒度按钮在各自阶段继续接入。

打开 Notebook 的顺序为：用户点击时预留空白窗口 → 读取对象 access → 检查 ready → 校验 URL 的来源与路径 → 本地模式在配置的独立来源调用 notebook-session → 跳转。拒绝带用户信息、query/hash 或不符来源的地址，初始化请求禁止重定向；Token 从不进入窗口 URL。外部身份模式不调用本地 notebook-session，保留已有可信代理认证。

部署时必须设置 `VITE_NOTEBOOK_ORIGIN`，与后端 `auth.notebook_origin` 一致；配置不是用户可填的地址。平台和 Notebook 使用 HTTPS、不同 hostname，推荐同站不同子域。跨站 Cookie 可能被浏览器策略阻止；初始化 API 返回成功不能证明用户浏览器最终接受了 Cookie。Notebook 自动续期尚未实现，Token 到期需回平台重新打开。

## 日志、诊断与数据真实性

详情页只挂载当前面板，不会进入详情就同时请求所有诊断接口。含内容的面板需要 notebook.connect 与对象归属判断；用量只依赖读取权限。查询键包含 groupId、实例 ID、revision 和 ownerRevision；版本/负责人改变后切换查询身份，日志/事件/诊断离开面板后不长期缓存。请求消费 AbortSignal，查询失败后停止该面板的自动轮询，页面不展示旧成功数据替代错误。

- 事件、诊断与用量每 15 秒读取一次；没有指标显示不可用，不显示假零值。
- 日志只读主容器最近一小时，100/200/500/1000 行可选，最多 256 KiB，支持 previous；用户可开启每 5 秒刷新，但不是流式 follow。
- 日志作为 React 文本渲染，不解析 HTML、脚本或 ANSI 控制码；没有自动保存到本地文件。
- GPU 实际使用量没有可信接口时明确不可用；空闲回收缺少可信活动源时明确告知。

## 空间与成员实施约定

`features/groups` 沿用 api / types / form-schema / policy / 页面 / components 分层。表单、成员表格、角色字段、短确认、配额表及授权落实列表各自维护职责，不把全局账号管理混入组内成员管理。

- 创建空间只提交后端支持的名称、展示名与初始配额；不提交 description、基础设施 owner 或虚构的创建时间。请求受理后查看操作与观测状态。
- 展示元数据不占用执行器 revision。后端 PATCH 支持可选字段及 expected 名称/描述快照，锁内比较旧值，避免覆盖他人更改；只有变化字段进入 updates。
- 成员 PUT 是完整替换语义，不是增量授权；提交前清晰说明。有效绑定额外返回现有 version，客户端提交 expectedBindings（id + version），后端锁内比较完整有效集合。只比较 ID 不够：撤销后再次授予同一个角色会复用绑定行，因此必须比较 version。
- 新增授权提交空 expectedBindings，仅允许目标当前没有有效组内角色；已有有效角色走编辑。移除复用 PUT roles=[] 及相同并发校验，保留最后负责人、活跃工作负载及数据保留规则。
- 不假设 group.member.manage 包含全局 user.read；组内管理不拉取全站用户目录。仅按既有用户 ID 操作，账号登记和目录管理留到全局管理阶段。
- 业务角色已保存、原生访问 desired/observed、落实版本、错误与操作单分开展示。撤权历史不能只靠当前成员列表展示，因此单独按 userId 分页读取 access。
- 负责人交接只管理业务角色，不改变 Profile owner；默认 keepCurrent=true。交接后返回空间选择页，避免撤销自己权限后仍留在受限页面。
- 配额读取依赖 group.quota.read，修改依赖 /me 的全局 group.quota.update。只接受后端真实快照；remaining 沿用后端计算，不在前端重新模拟预算分配。调整需要 revision 与原因，CPU / 内存精度和 Kubernetes 数量解析由后端负责。
- 元数据、成员/授权、配额写操作沿用会话内同意图幂等键；失败不清空输入，不自动强行刷新修订覆盖。权限快照失败时停止写入口；资源查询失败不把旧记录包装成最新结果。
- 停用/恢复/删除要求空间名与原因确认。删除非空空间仍由后端拒绝，不新增“强制删除全部资源”开关。操作终态更新相关列表缓存；角色保存操作终态不等于独立授权任务已 READY。

兼容扩展没有新表或迁移，不替换 GORM，不改后端既有路由组织。未运行类型检查、测试、编译或真实集成验证。

## 平台管理实施约定

- `features/admin` 继续按 api、types、form-schema、policy、页面、职责组件分层；`features/security` 单独封装设备会话契约，供自己的账号安全页与管理员目标用户面板复用，不把 session 当作组内资源。
- 公共 `useGlobalPermissions` 只读取 `/me` 全局权限。平台管理与空间导航分开；无 user.read 不显示全站用户目录，无 role.manage 不读取角色目录和他人的全局绑定。
- 登记本地账号时不接受客户端指定 issuer/subject，也不同时提交密码；外部身份按 issuer + subject 核验，不能按邮箱自动合并或迁移身份。切换登记类型改变 query 参数，未保存拦截器显式监测 search 变化，防止切换时丢草稿。
- 用户详情新增只读 localAccount 标志，来自后端当前认证域配置，不让浏览器按 issuer 字符串猜测是否允许重置本地密码。
- 用户启用/禁用可携带 expectedAuthorizationVersion，角色定义编辑可携带 expectedVersion，锁内冲突返回 409；未改变请求沿用同一个会话内幂等键。角色/绑定 PUT 是后端明确的整体替换语义，不作为普通字段 PATCH 使用，界面提示影响范围并锁定原版本。
- 内置角色不提供编辑或停用；自定义角色的编码与 scope 创建后固定。权限只从后端字典显式选择，不推导通配符；空间工作负载权限仍需对应 view/edit 原生访问级别，后端最终校验。
- 密码仅在本地表单及发送请求期间存在，不作为 mutation variables 或 useCommandKey 的输入；成功/取消后清空。重置接口不是业务 Operation 幂等命令，遇到不确定失败不自动重试，不把按钮重试包装成幂等重放。
- 设备会话查询按 family 游标分页，活跃面板每 30 秒读取、错误后停止轮询、离开不长期保留。撤销当前设备或全部退出后清理内存认证与查询缓存；管理员查看仅限当前认证域，服务端在授权锁内重新检查当前会话、凭据和 user.manage。
- 已失权或内容请求 401/403 时不继续呈现旧角色/审计/设备数据。普通网络失败下保留非敏感表单草稿并关闭写入口；确认撤权后优先隐藏受限数据。
- 用户与审计没有伪造服务端搜索：客户端只筛选已加载记录，支持继续加载；审计保持后端 ID 正序且关联操作再授权。统一操作运维台、服务端筛选、审计导出尚未实现。

本轮只修改源码、文档及格式，没有新增或运行测试，也未类型检查、编译、启动或迁移。

## Notebook 目录与交接实施约定

- `features/storage` 独立维护目录 api / types / form-schema / policy / cache / 页面 / 组件；目录是数据资产，不与空间选择的 `features/workspaces` 混用。`features/ownership` 只复用两个交接流程的输入与表单，端点、权限、状态检查与缓存更新仍各归所属模块，不抽象万能资源 CRUD。
- 路由为 `/g/:groupId/storage`、`storage/:workspaceId`、`storage/:workspaceId/transfer` 和 `notebooks/:notebookId/transfer`。导航依赖 workspace.read，实例交接另外使用 notebook.transfer / notebook.transfer.any，不拿 notebook.read.any 代替交接权限。
- 目录列表 after 分页每页 50 条，列表/详情 10 秒更新，失败停止自动读取。筛选只作用于已加载页；实际使用量空值如实展示，不混同 capacityBytes。没有新增文件浏览、磁盘指标、PVC 认领或备份接口。
- 创建复用目录分页选择属于当前用户、独占身份已确认且没有历史引用的资产，提交 workspaceId + workspaceRevision，并继续提交有效 workspaceSize 作为最小容量。创建的复用选择不允许借管理员身份为新建实例挂载其他人的目录；服务端仍在原事务内重验归属/容量/UID/引用。
- 关联/解除确认在可见弹窗中读取具体 Notebook，含已删除历史实例；使用独立查询键、AbortSignal 和 gcTime=0。提交目录 revision + notebookRevision；不自动停止、替换已有目录或启动实例。未知失败重放原请求体和原幂等键，版本冲突须关闭后重新核对，不自动改用新的 Notebook 版本。
- 实例转移使用 ownerRevision，目录转移使用自身 revision。先停止并交接实例，再交接数据，或者先安全解除引用；交接不是复制文件。目标按空间有效成员 ID 输入，不要求访问全站用户目录。两个表单固定首次新鲜读取的基线，背景读取不会自动覆盖草稿或换版本。成功返回列表，异步结果不导航回已离开的页面。
- 目录删除独立确认 PVC 名、处置原因及现有 retained 保护解除；关联/历史引用未清理不允许提交，不提供强制删除。202 与 operation 终态都不替代实际资源观测。
- 写操作受理与操作单终态更新目录、Notebook 相关缓存。普通网络错误保留非敏感草稿并关闭写入口；确认撤权/404 后隐藏旧数据。Notebook 返回新增 workspaceId 只用于关联导航，0 表示没有登记 attachment，不代表文件不存在，也不构成目录访问授权。
